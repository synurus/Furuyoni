# 후루요니 AI 시뮬레이터 작업 계획서

> 목표: 기본 4여신(유리나·사이네·히미카·토코요) 기반 게임 엔진을 구축하고,
> AI끼리 자동 대전 및 "상황별 최선의 수"를 탐색하는 시뮬레이터를 만든다.
> Google AI Studio(Gemini)는 ① 개발 조수, ② AI 플레이어(해설/보조)로 활용한다.

| 자료 | 상태 | 용도 |
|---|---|---|

## Phase 0 — 데이터 정비 (예상: 전체 작업의 30%)

**목표: 기계가 읽을 수 있는 정확한 카드 데이터 완성**

- [ ] 0-1. 카드 데이터 파일 업로드 및 현황 파악
- [ ] 0-2. 최신 패치와의 차이(diff) 목록 작성 — 사용자가 패치노트 제공 또는 함께 웹 확인
- [ ] 0-3. 표준 카드 JSON 스키마 확정 (아래 초안 참고)
- [ ] 0-4. 4여신 × (통상패 7 + 비장패 4) = **44장** 데이터를 스키마에 맞게 변환·검수
- [ ] 0-5. 룰북에서 "게임 상수" 추출 → `constants.json`
      (초기 라이프 10, 오라 3, 간격 10, 더스트 0, 손패 상한 2, 집중력 상한 2, 벚꽃결정 총량 등)

**카드 스키마 초안:**
```json
{
  "id": "NA-01-yurina-O-N-1",
  "owner": "yurina",
  "name": "참",
  "type": "attack",            // attack | action | enhancement(부여)
  "subtypes": [],              // 대응, 전력 등
  "range": [3, 4],             // 적정거리
  "damage_aura": 3,
  "damage_life": 1,
  "cost_flare": null,          // 비장패 소모값
  "vigor": null,               // 봉납 (부여패)
  "text_raw": "카드 원문 텍스트",
  "effects": [                 // 구조화된 효과 (엔진이 해석)
    { "trigger": "attack_hit", "op": "...", "params": {} }
  ],
  "patch_version": "2025-XX"
}
```
> `effects` 구조화가 이 프로젝트에서 가장 까다로운 부분.
> 44장이면 효과 종류가 한정적이라 수작업+Gemini 보조로 충분히 가능.

## Phase 1 — 게임 엔진 (Python) (30%)

**목표: 룰북대로 정확히 돌아가는 결투 엔진**

- [ ] 1-1. `GameState` 클래스: 라이프/오라/플레어/집중력/위축, 간격/더스트, 손패/패산/버림패/덮음패/봉인, 부여패, 턴/페이즈
- [ ] 1-2. 벚꽃결정 보존 법칙 검증기 (전체 결정 수가 항상 일정한지 매 수마다 체크 → 버그 조기 발견)
- [ ] 1-3. 턴 구조 상태머신: 개시(간격결정→효과→기정처리) → 메인(표준/전력행동) → 종료 (룰북 8장 그대로)
- [ ] 1-4. 기본동작 7종 구현 (전진/후퇴/이탈/纏い(감싸기)/宿し(불태우기)/카드뽑기 등 — 룰북 명칭 기준)
- [ ] 1-5. 공격/데미지 해결 파이프라인: 적정거리 판정 → 대응 창(window) → 오라/라이프 선택 → 수치수정 적용순서(룰북 5-6)
- [ ] 1-6. 카드 효과 인터프리터: Phase 0의 `effects` 구조를 해석 실행
- [ ] 1-7. **합법 수 생성기** `legal_moves(state) -> list[Move]` ← AI의 필수 재료
- [ ] 1-8. CLI 대전 모드 (사람 vs 사람 텍스트 플레이로 육안 검증)

**단순화 결정 (v1 스코프):**
- 쌍장요란(여신 선택)·안전구축(덱 구축)은 **고정 덱 프리셋**으로 대체 → 결투만 먼저
- 어나더 여신(제1장 유리나 등) 제외, 오리진 4여신만
- 안전구축 AI는 v2 과제로 이월

## Google AI Studio 활용 지점

| 시점 | 활용 방법 |
|---|---|
| Phase 0 | 카드 텍스트 → effects JSON 변환 초안 생성 (사람이 검수) |
| Phase 1 | 엔진 코드 작성 보조 (본 대화의 Claude와 병행 가능) |
| Phase 3 | AI 플레이어 프롬프트 설계·테스트 (AI Studio 무료 환경) → 확정 후 Gemini API 코드화 |
| Phase 4 | 추천 수 해설 생성 |

**주의:** Gemini API 무료 등급은 분당 요청 제한이 있어 대량 self-play에는 부적합.
대량 시뮬레이션(Phase 2, 4)은 로컬 Python 엔진으로만 수행한다.
