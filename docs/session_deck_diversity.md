# 세션: 덱 다양성 — 같은 조합이면 늘 같은 10장이던 문제 (2026-09-14)

## 요약

`ai/deckbuild.py`의 `pick_deck()`이 `rng`를 인자로 받으면서 **본문에서 쓰지 않아**,
같은 여신 조합이면 자기대국 수천 판이 전부 동일한 10장으로 진행되고 있었다.
점수에 비례한 확률 표집으로 바꿔 덱 다양성을 만들었다. 실측상 덱 가짓수는
3배로 늘었고 덱 강도는 떨어지지 않았다.

## 발견 경위

프로젝트 목표(여신 추천 / 밴 추천 / 덱 구축 추천 / 실시간 행동 추천)를 정리하면서
안전구축이 엔진에 구현돼 있는지 확인하다 세 가지가 같이 나왔다.

### (1) 안전구축은 이미 구현돼 있다

README의 "안전구축·무다시는 v2" 메모는 낡았다. `PLAN_deckbuild.md`에 2026-07-08
완료로 기록돼 있고, `build_two_megami_deck()`이 통상14풀→7, 비장8풀→3을 고른 뒤
미선택 카드를 `p.out_of_game`으로 보낸다.

### (2) 봇은 상대가 무엇을 골랐는지 안다 — 미해결

```python
pool = list(opp.hand) + list(opp.deck) + list(opp.covered)
rng.shuffle(pool)
```

`mcts.determinize()`는 이 셋만 섞는다. `out_of_game`은 건드리지 않으므로 **상대가
고른 10장이 무엇인지는 그대로 유지**되고, 섞이는 것은 "그 10장 중 어느 것이 손에
있나"뿐이다.

안전구축은 비공개 선택이므로 실제로는 불확실성이 2층이다.

| 층 | 모르는 것 |
|---|---|
| 1 | 상대가 어떤 10장을 골랐나 |
| 2 | 그중 지금 손에 있는 것은 무엇인가 |

지금 구현은 2층만 다룬다. 1층을 채우는 것이 "실시간 행동 추천" 기능의 본체다.
이번 세션에서는 손대지 않았다 — 한 번에 하나씩 바꿔야 원인 해석이 흐려지지 않는다.

### (3) 덱이 항상 똑같다 — 이번에 고친 것

`pick_deck(meg_a, meg_b, rng)`가 `rng`를 받고도 쓰지 않고 점수 상위를 그대로 잘랐다.
세 곳에 동시에 타격이 있었다.

- **학습** — 가치망이 조합당 덱 하나에만 맞춰진다. B-4 세션이 다룬 "데이터 다양성"은
  봇 풀과 탐색 노이즈였고, 그것은 *플레이*만 흔들지 *덱 구성*은 고정이었다
- **덱 구축 추천** — 추천할 것이 없다. 답이 언제나 하나다
- **실시간 행동 추천** — 1층 사전분포를 만들 재료가 없다. 분포가 아니라 점 하나다

## 수정

`_take()`를 추가해 점수를 가중치로 삼는 중복 없는 표집을 하고, `_balanced_pick()`이
이를 쓰도록 했다. 여신별 최소 확보(통상 2장 / 비장 1장)는 그대로다.

```python
SAMPLE_TEMP = 1.2   # 작을수록 상위 쏠림, 클수록 고르게

def _take(pool, k, score_fn, rng):
    if rng is None:                      # 종전 동작 유지
        return sorted(pool, key=score_fn, reverse=True)[:k]
    ...                                  # exp((s - top) / SAMPLE_TEMP) 가중 표집
```

- `rng=None`이면 예전처럼 확정적으로 상위를 자른다 (기존 호출부 보호)
- `new_game_2v2` → `build_two_megami_deck` → `pick_deck`으로 게임 rng가 이미
  전달되고 있었으므로 **배선 변경은 없었다**. 받아만 놓고 안 쓰던 것을 쓰게 했을 뿐
- 표집도 rng가 결정하므로 **seed를 고정하면 그대로 재현된다**

## 온도 선택 (실측)

각 온도에서 덱 가짓수(300회 표집, 6개 조합 평균)와 확정덱 상대 승률(heuristic 봇,
240판, 표집 쪽을 번갈아 배정).

| 온도 | 덱 가짓수 / 300 | 표집덱 승률 |
|---:|---:|---:|
| 0.6 | 31.2 | 47.1% |
| **1.2** | **95.5** | **47.9%** |
| 2.0 | 198.5 | 44.6% |
| 4.0 | 287.5 | 40.0% |

1.2를 택했다. 0.6 대비 가짓수가 3배인데 승률은 같고, 그 위로는 강도가 깎인다.
4.0의 40%는 예전에 기록된 기계적 분배 덱 수준(스마트덱 상대 40%)에 가깝다.

승률 47.9%는 확정덱보다 약간 낮지만 240~672판 규모에서 표준오차가 2~3%p라
50%와 구분되지 않는다. **다양성을 덱 강도 손실 없이 얻었다**고 본다.

## 다음에 주의할 것

이번 변경 이후의 학습 결과는 **이전 데이터와 직접 비교하면 안 된다.** 덱 분포가
달라졌으므로 승률 숫자의 기준선이 바뀐다. 진행 중이던 600/60 실행(커밋 05d7fe3)은
특징 누수 수정만 반영된 것이고, 덱 표집은 그다음 실행부터 적용된다.

변수를 하나씩 분리하려면 순서는 이렇다.

1. 누수 수정의 효과 — 진행 중인 실행 결과로 판단
2. 덱 다양성의 효과 — 그다음 실행
3. `determinize`의 1층 — 그 뒤
