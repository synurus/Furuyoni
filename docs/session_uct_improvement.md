# UCT 개선 시도 및 결론 (2026-07-08)

## 배경
tune_uct.py 기록: UCT iters 160→400 증량 시 오히려 악화 → "예산 문제가 아니라 구조 문제" 추정. 개선 후보로 리프 평가, 짧은 롤아웃, 강한 prior, 평가함수 고도화가 제시됨.

## 시도한 개선들과 실측 (vs 휴리스틱)
| 방법 | 승률 |
|---|---|
| 기존 롤아웃 UCT iters160 | ~29% |
| 리프평가 UCT (롤아웃 제거) iters120 | 29% |
| 짧은 롤아웃 H=2 | 29% |
| 강prior(n0=8)+저탐험(c=0.3)+리프평가 | 25% |
| 2수 앞 LookaheadBot | 32% |

기본 능력 확인:
- 리프평가 UCT vs 랜덤: **100%** (탐색 자체는 정상 작동)

## 결론: 얕은 탐색은 이 게임에서 구조적 열세

**핵심 원인 3가지:**
1. **평가함수가 이미 강력**: 1수 앞 휴리스틱이 강해서 트리 탐색의 한계이득이 작음.
2. **불완전정보 + 높은 분기**: determinize 노이즈가 크고 트리가 얕고 넓게 퍼짐. 단일 트리인 UCT는 노이즈에 취약(MC는 다수 결정화 앙상블로 상쇄).
3. **가변 길이 턴 구조**: 후루요니는 한 턴에 기본동작+카드 여러 장을 둠. 얕은 미니맥스(2수 앞)는 "턴이 한 수로 끝난다"고 가정해 상대 반응을 조기 계산 → 왜곡. 그래서 2수 앞이 1수 그리디보다 오히려 약함.

**최종 판단:**
- 챔피언은 **MonteCarloBot(K=48)** 유지가 정답. MC는 다수 결정화의 평가 평균으로 노이즈를 상쇄하는데, 이것이 이 게임에 가장 잘 맞음.
- UCT/LookaheadBot은 연구·비교용으로 보존하되 챔피언 후보에서 제외.
- **추가 개선의 올바른 방향**: 탐색 알고리즘이 아니라 **평가함수 자체의 고도화**(위협 인식, 자원 임계 가치, 다음 턴 콤보 잠재력 등). 평가함수가 강해지면 MC/휴리스틱 모두 동반 상승.

## 코드 변경
- uct.py: leaf_eval 옵션 추가 (랜덤/약체 상대 빠른 UCT용). 챔피언 아님.
- heuristic.py: LookaheadBot 추가 (실험체, 경고 주석 포함).
- tune_uct.py: 최종 결론 기록.

## 배운 것
"더 깊은 탐색 = 더 강함"은 이 게임에서 성립하지 않는다. 게임 구조(불완전정보, 가변 턴, 자원 축적)가 알고리즘 선택을 지배한다. MC 하이브리드가 최적점이라는 것을 여러 대안의 실측으로 확정.
